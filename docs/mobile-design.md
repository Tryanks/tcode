# tcode 手机端设计规范

状态：权威规范（2026-09-05）。手机端（iOS / Android，以及后续的浏览器端）
一切界面、文案、交互以此为准；与代码冲突时改代码。配套计划见
`docs/plans/remote-and-mobile.md`。

## 0. 产品定位：一台随身的「监督器」

手机端不是缩小的桌面版，更不是 IDE。它做且只做四件事，按频率排序：

1. **看**：哪些对话在跑、跑到哪、有没有卡住或出错。
2. **批**：执行端弹出的权限请求，在手机上一键放行或拒绝。
3. **说**：追加一句话、引导正在进行的轮次、打断。
4. **开**：在某个项目里新开一个对话，把任务派出去。

所有真正的工作都在**执行端**（Mac 或服务器上的 tcode）完成；手机端只是它
的一块屏幕。这个前提决定了整个界面：没有终端、没有 diff 编辑、没有文件
选择器、没有本地设置项。

## 1. 术语表（最终裁定）

界面文案、代码标识、文档一律使用下表。桌面端「设置 → 远程」里凡是指
「运行 tcode 主机进程的那台机器」的「主机」，一并改为「执行端」。

| 概念 | 简体中文 | English | 说明 |
|---|---|---|---|
| 运行任务的那台 tcode | 执行端 | Host | 用户原话。不用「主机 / 服务器 / 远程端」 |
| 手机上的 tcode | 手机端 | tcode for iPhone / Android | 只在「关于」里出现产品名 |
| 手机在执行端眼中 | 设备 | Device | 执行端的「已配对设备」列表 |
| 建立信任的过程 | 配对 | Pair / Pairing | 动词「配对」，名词「配对」 |
| 六位数字 | 配对码 | Pairing code | 不叫「口令 / 验证码 / PIN」 |
| `tcode://pair?...` | 配对链接 | Pairing link | 二维码的内容 |
| 扫二维码 | 扫码配对 | Scan QR code | |
| 项目（工作目录） | 项目 | Project | 与桌面端一致 |
| 一段会话 | 对话 | Thread | 与桌面端一致，不用「线程 / 会话 / 任务」 |
| 新建 | 新建对话 | New thread | |
| 一次请求-响应 | 轮次 | Turn | 「停止当前轮次」 |
| 正在生成 | 工作中 | Working | 与桌面端一致 |
| 等权限 | 待审批 | Needs approval | 与桌面端一致 |
| 等用户答题 | 待回答 | Needs your answer | 与桌面端一致 |
| 新内容未看 | 未读 | Unread | |
| 结束的对话 | 已完成 | Done | 列表副标题用；无轮次在跑 |
| 出错 | 出错 | Failed | 列表副标题用 |
| 追加发送（等本轮结束） | 排队 | Queue | 与桌面端一致 |
| 插入本轮 | 引导 | Steer | 与桌面端一致，不用「插话 / 打断」 |
| 中止 | 停止 | Stop | |
| 工具活动折叠组 | 工作日志 | Work log | 与桌面端一致 |
| 思考 | 思考中 / 已思考 | Thinking / Thought | 与桌面端一致 |
| 允许一次 | 允许 | Allow | 审批按钮 |
| 本对话内不再问 | 本对话始终允许 | Always allow in this thread | 审批的第三个动作 |
| 拒绝 | 拒绝 | Deny | |
| 审批模式 | 审批模式 | Approval mode | 三档：监督模式 / 自动接受编辑 / 完全访问 |
| 模型 | 模型 | Model | |
| 推理强度 | 推理强度 | Effort | 与桌面端一致 |
| 连接状态 | 已连接 / 正在连接 / 重连中 / 离线 | Connected / Connecting / Reconnecting / Offline | 见 §4 |
| 手机自己的名字 | 本机名称 | This device's name | 配对时上报给执行端 |

英文文案风格：句首大写、无句号的短标签；正文句子完整。中文文案：不用
「您」，不用感叹号，标点用全角，数字与中英文之间留空格。

## 2. 信息架构

```
启动
 ├─ 有「上次使用的执行端」 → 直接进入 [对话列表]（顶部显示「正在连接…」）
 └─ 否则 → [执行端]

[执行端]  ──点执行端──▶  [对话列表]  ──点对话──▶  [对话]
   │                        │  ├─ ＋ ──▶ (选择项目) ──▶ [对话]（新草稿）
   ├─ 配对 ──▶ (配对)        │  └─ ⚙ ──▶ (设置)
   └─ 长按 ──▶ (移除执行端)   └─ ‹ 执行端（返回，断开连接）
```

- 三级栈：执行端 → 对话列表 → 对话。方括号是全屏页，圆括号是从底部升起
  的 sheet。
- 返回：iOS 用左上角「‹ 上一级」文字按钮；Android 同时响应系统返回键。栈底
  再按返回 = 退出应用。
- 切换执行端就是回到 [执行端] 再点另一个。一次只连一个执行端。
- 没有 tab bar。三个层级是线性的，tab 会把「执行端」和「对话」并列，误导用户。

## 3. 各屏幕

### 3.1 执行端（启动页）

**目的**：让用户在 1 秒内知道「我能连哪台机器」，并且永远有一条路去配对。

- 大标题「执行端」（28 pt semibold）。右上角无按钮。
- 列表：每台已配对执行端一张卡片（高 ≥ 72 pt，圆角 12，`secondary.background`）：
  - 第一行：执行端名称（17 pt semibold）。若是上次使用的，右侧一枚灰色胶囊
    「上次使用」。
  - 第二行（14 pt muted）：`192.168.1.6:47420 · 3 分钟前连接过` /
    `… · 从未连接`。多地址只显示第一个。
  - 右侧 chevron。整卡可点。
  - 长按（桌面预览：右键）→ sheet「移除执行端“名称”？移除后需要重新配对。」
    [取消] [移除]（红色）。
- 底部固定主按钮（高 50，圆角 12，主色）：「配对新的执行端」。
- 空状态（无卡片时替换列表区）：居中，标题「还没有配对的执行端」（20 pt
  semibold），正文（16 pt muted，最多三行）：「在 Mac 或服务器上运行 tcode，
  打开“设置 → 远程”开启托管并显示配对码，然后在这里配对。手机只负责查看
  和操作，所有任务都在执行端上运行。」主按钮同上。
- 点某个执行端：**立刻**进入对话列表，由对话列表显示连接进度；本页不转圈。

### 3.2 配对（sheet）

**目的**：三十秒内完成，且每一步的失败都能说清楚原因。

- 标题「配对执行端」，右上角「取消」。
- 若平台支持相机：顶部一枚大按钮「扫码配对」（高 50，主色描边风格）；下方
  分隔文字「或手动输入」。不支持时不显示这一段，不显示任何「不支持」提示。
- 表单（每项：13 pt 标签在上，输入框高 48）：
  - 地址：占位 `执行端的 IP 或主机名`，键盘 URL 类型。
  - 端口：默认 `47420`，数字键盘。
  - 配对码：占位 `六位数字`，数字键盘，等宽字体 24 pt，字间距放大。
- 说明文字（14 pt muted）：「配对码显示在执行端的“设置 → 远程”，或由
  `tcode-headless pair` 打印，5 分钟内有效。」
- 任何输入框里粘贴 `tcode://pair?...` 链接 → 自动拆解填入三项，并提示
  「已从配对链接填入」。扫码成功走同一路径。
- 主按钮「配对」（三项合法前置灰）。进行中变为「正在配对…」并禁用表单。
- 错误（表单上方一条红色文本，不用弹窗）：
  - 配对码错误或已过期 → 「配对码错误或已过期，请在执行端重新生成」
  - 连接超时 / 拒绝连接 → 「无法连接到 192.168.1.6:47420，请确认手机和执行端
    在同一网络」
  - 其他 → 「配对失败：{原因}」
- 成功：保存到 `hosts.json`，关闭 sheet，自动连接并进入对话列表。

### 3.3 对话列表

**目的**：一眼看出「哪个对话需要我」。

- 顶栏（高 52 + 安全区）：左「‹ 执行端」；中间两行：执行端名称（17 pt
  semibold）+ 连接状态（§4，13 pt）；右侧「＋」和「⚙」两枚 44×44 图标按钮。
- 内容按项目分组：
  - 组头：项目名（13 pt semibold，muted，不全大写，中文不需要）+ 右侧对话
    数量。组头上边距 24，下边距 8。
  - 行（高 ≥ 64，左右内边距 16）：
    - 左侧 20×20 状态位：工作中 = 主色旋转圈；待审批 = 琥珀色圆点带感叹号；
      待回答 = 主色问号圆点；未读 = 主色实心小圆点；其余留空。
    - 第一行：对话标题（16 pt，单行省略）。未读时 semibold。
    - 第二行（14 pt）：`状态 · 相对时间`。状态词：工作中（主色）/ 待审批
      （琥珀色 semibold）/ 待回答（主色 semibold）/ 出错（红色）/ 已完成
      （muted）。相对时间：刚刚 / 5 分钟前 / 昨天 / 9 月 3 日。
    - 待审批与待回答的行整行加 6% 琥珀色/主色底，让它在列表里跳出来。
  - 排序：组内按最后更新倒序；组的顺序沿用执行端设置里的项目排序。
  - 未发送的草稿不进列表（草稿只存在于「＋」流程里，退出即丢弃）。
- 「＋」→ sheet「在哪个项目新建对话」：项目列表，点一项 → `StartDraft` →
  进入空白对话页并聚焦输入框。只有一个项目时跳过 sheet。
- 空状态：「这台执行端上还没有项目」+「在执行端上添加项目后，会自动出现在
  这里。」不提供在手机上添加项目（那需要在执行端选目录）。
- 正在连接（尚无快照）：显示 3 行 30% 透明度的占位行 + 状态「正在连接…」。
- 离线：列表保留上次的副本，状态「离线」，行可点进去只读。

### 3.4 对话

**目的**：读得舒服、批得快、说得上话。

- 顶栏：左「‹ 对话」；中间：对话标题（17 pt semibold，单行省略）+ 副标题
  项目名（13 pt muted）；右侧：仅在非「已连接」时显示连接状态胶囊。
- 时间线（可滚动，左右内边距 16，段落间距 12）：
  - 用户消息：右对齐灰色气泡（`secondary.background`，圆角 16，最大宽 85%），
    16 pt。附件仅显示文件名 chip。
  - 助手回复：无气泡、通栏、Markdown 渲染（复用 `tcode_ui::markdown`），
    代码块横向可滚动，14 pt 等宽。
  - 思考：一行「思考中…」（muted）→ 完成后「已思考 · 12 秒」，点开可读。
  - 工作日志：每个轮次一张折叠卡「工作日志 · 12 次工具调用 · 3 处编辑 ·
    2 条命令」（默认折叠；进行中显示最新一条活动的一行摘要并转圈）。展开后
    每条活动一行：图标 + 简述（`读取 src/main.rs` / `$ cargo test`），命令
    输出再点一次才展开，最多 20 行。
  - 计划：卡片「计划 3/7」+ 进度条，展开列步骤，完成项打勾。
  - 出错：红色左边线卡片，标题「出错」，正文错误信息。
  - 轮次结束：无额外页脚；模型名不在时间线里重复出现。
- **审批卡**（不在时间线里，**固定在输入框上方**；有多条时叠放，最早的在上）：
  - 琥珀色 3 px 左边线，标题按类型：「请求执行命令」/「请求修改文件」/
    「请求读取文件」；正文：命令（等宽，最多 6 行，可展开）或文件列表。
  - 按钮两行：第一行 [拒绝]（次要，等宽）[允许]（主色，等宽）；第二行文字
    按钮「本对话始终允许」。每个按钮高 44。
  - 离线时按钮禁用并提示「离线，重连后可操作」。
- **待回答卡**（同样固定在输入框上方）：问题正文 + 选项列表（单选/多选
  chip，高 44）+ 可选的「其他」文本框 + 主按钮「提交」。
- 队列条（有排队消息时，在输入框上方、审批卡之下）：每条一行「排队中 ·
  消息前 40 字」+ 右侧两个文字按钮「引导」「移除」。
- 输入区（底部固定，随键盘上移，背景与页面同色，上方一条渐隐发丝线）：
  - 左：模型 chip（胶囊，13 pt，`Sonnet 5 · 高`，点 → 3.5）。
  - 中：输入框（圆角 16，最小高 44，最多长到 5 行，16 pt），占位「发消息…」。
  - 右：圆形主按钮 40×40：空闲 = 发送（箭头）；轮次进行中 = 停止（方块，
    红色）。**进行中时点发送箭头 = 排队**（箭头旁小字「排队」）。
  - 桌面预览：Enter 发送，Shift+Enter 换行。手机：只靠按钮。
  - 离线：输入框可编辑但按钮禁用，占位改为「离线，重连后可发送」。
- 有新内容且用户不在底部时，右下角出现胶囊「↓ 新内容」，点击滚到底。发送
  自己的消息后总是滚到底。

### 3.5 模型与模式（sheet，从模型 chip 进入）

- 标题「模型」。
- 分组：按配置（provider profile）分组，行为模型名 + 右侧收藏星；当前项
  打勾。顶部「收藏」组先列收藏的模型。
- 若当前提供方支持：分段控件「推理强度」：低 / 中 / 高 / 最高（沿用桌面端
  可选项与文案）。
- 分段控件「审批模式」：监督模式 / 自动接受编辑 / 完全访问，下方一行说明
  （与桌面端相同文案）。这一项放在这里是因为手机端最常做的调整就是「少问我」。
- 选择即生效并关闭（模型），或即时生效不关闭（分段控件）。

### 3.6 设置（sheet，从 ⚙ 进入）

- 外观：跟随系统 / 浅色 / 深色（分段控件）。
- 语言：跟随系统 / English / 简体中文。
- 本机名称：文本框，默认取设备名（iPhone 名称 / Android 型号）。
- 关于：版本号、协议版本。
- 底部红色文字按钮「断开并返回执行端列表」。
- 手机端**没有**提供商、审批默认值、编排等设置；那些属于执行端。

## 4. 连接状态（贯穿全局）

| 状态 | 文案 | 样式 | 触发 |
|---|---|---|---|
| 正在连接 | 正在连接… | 旋转圈 + muted 文字 | 首次连接尚未收到快照 |
| 已连接 | 已连接 | 绿色小圆点 + muted 文字；对话页不显示 | 链路正常 |
| 重连中 | 重连中 · 第 3 次 | 琥珀色旋转圈 + 琥珀色文字 | 掉线后自动重试 |
| 离线 | 离线 | 红色圆点 + 红色文字 | 连续失败超过 30 秒后 |

- 状态只在顶栏副标题（列表页）和顶栏右侧胶囊（对话页，非已连接时）显示，
  不用横幅、不用弹窗、不用 toast。
- 应用回到前台立刻重试一次，不等退避计时。
- 「离线」不清空任何内容：列表和时间线保留最后的副本，只禁用会写入执行端
  的动作。

## 5. 视觉系统（手机专用值）

沿用 `docs/DESIGN.md` 的字体与色板（`themes/tcode.json`），手机窗口不透明，
画布色压平（同桌面无 vibrancy 时的处理）。

| 项 | 值 |
|---|---|
| 字体 | UI：系统字体（iOS San Francisco / Android Roboto，CJK 由系统级联）；等宽：系统等宽 |
| 字号 | 大标题 28/34 semibold · 标题 17/22 semibold · 正文 16/22 · 次要 14/20 · 说明 12/16 · 等宽 14/20 |
| 边距 | 页面左右 16 · 卡片内 14 · 列表行上下 12 · 组头上 24 下 8 |
| 圆角 | 卡片 12 · 按钮 12 · 输入框 12 · 输入区 16 · 胶囊 full |
| 高度 | 主按钮 50 · 次按钮 44 · 输入框 48 · 列表行 ≥ 64 · 顶栏 52 |
| 触控 | 任何可点元素 ≥ 44×44；按下态 8% 叠色；无 hover、无 tooltip、无右键菜单（桌面预览的右键仅映射长按） |
| 色彩 | 工作中 = primary · 待审批 = warning · 待回答 = primary · 出错 = danger · 已连接 = success · 重连中 = warning · 离线 = danger |
| 安全区 | 顶部状态栏、底部 home 指示条、键盘：分别用 `WindowInsets` 的 safe_area / ime 处理，内容永远不被遮挡 |
| 动效 | 仅旋转圈；页面切换直接替换，不做过渡（v1） |
| 深浅色 | 默认跟随系统 |

## 6. 不做的事（v1 明确排除）

终端、预览浏览器、diff 面板、文件 @ 补全、附件上传、语音输入、归档管理、
重命名、搜索、多执行端同时连接、后台推送通知。以上都有存在理由，但都不在
「监督器」的前四件事里。

## 7. 验收

- 每个屏幕的每种状态（含空态、连接中、离线、错误）都有截图，逐张对照本
  规范；文案逐字对照 §1 与各屏幕小节；`locales/zh-CN.yml` 与 `en.yml` 的
  `mobile.*` 键同步。
- 真机流程：iPhone 模拟器与 Android 模拟器分别对本机上的 `tcode-headless`
  完成：配对 → 看到项目与对话 → 新建对话并发送一轮 → 在手机上审批 →
  杀掉执行端看到「重连中」→ 重启执行端自动恢复。
