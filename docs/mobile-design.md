# 手机与浏览器界面

本文记录当前紧凑界面的分工和交互；共享视觉规则见 [DESIGN.md](DESIGN.md)，
安装、配对、TLS 与连接限制见 [remote.md](remote.md)。实现或产品决定变化时同步
修订，不保留多版相互覆盖的裁决。

## 范围与组件归属

iOS、Android 和浏览器复用 `tcode-mobile` 外壳。它们连接一台执行端，查看对话、
发送或排队消息、引导或停止轮次、响应审批和问题，并在已有项目中创建对话。
项目文件、提供方进程和任务执行留在执行端。

`crates/mobile` 负责执行端列表、配对、导航和本机偏好。
`crates/ui` 的 `SessionsSidebar`、`ChatView`、`Composer`、`CommandPalette`
和 `OverlayHost` 负责共享界面；紧凑模式在这些组件内调整排版。
手机和浏览器隐藏终端、预览、diff 面板、文件选择、附件上传、语音和输入触发菜单。
搜索复用命令面板；侧栏保留共享的对话操作，不能把“紧凑”解释为重新实现一套状态机。

## 导航与本机偏好

页面栈为 **执行端 → 对话列表 → 对话**。启动时尝试连接上次使用的执行端；没有
记录时停在执行端列表。返回列表保留连接，返回执行端页断开连接。一次只连接一台
执行端，移除记录时也清除对应的上次使用记录。Android 系统返回复用页面返回路径，
栈底返回由宿主处理。

外观、语言和本机名称属于客户端。原生偏好保存在 `mobile.json`，配对凭据存储规则
见远程指南；浏览器由自己的宿主实现存储。iOS 使用设备名称、Android 使用设备型号
初始化本机名称。

页面 push/pop 使用 `NavStack` 的 200ms 过渡，手机外壳 sheet 使用 180ms
出现/消失过渡。共享模型和审批选择器保留各自的状态与内容，只改用底部 sheet
容器；紧凑选择器保持固定位置，内容随遮罩淡入淡出。

## 页面与交互

- **执行端**：显示名称、地址、上次使用记录和已有的证书指纹；卡片连接执行端，
  移除操作只删除客户端记录，不撤销执行端上的设备令牌。
- **配对**：支持手动输入、原生二维码扫描和可用平台上的附近发现。发现结果填入
  地址、端口和指纹，仍需配对码。配对结果显示指纹确认；浏览器固定使用页面来源，
  TLS 信任由浏览器管理，页面上的指纹不是证书校验。
- **对话列表**：顶栏提供新建和设置，搜索调用共享命令面板；内容复用紧凑侧栏。
  桌面侧栏的布局/排序/添加标题栏不重复显示，手机导航不保留桌面的常驻选中高亮。
  新建对话在需要时选择执行端项目。
- **对话**：顶栏显示标题与项目；共享时间线隐藏桌面标题栏和面板开关。新草稿有
  空态说明并聚焦输入框。复制在触屏上可见，不依赖 hover。
- **输入区**：模型、参数、审批和 Build/Plan 控件可换行以保持触控区域。空闲时发送；
  运行且无草稿时停止；运行且有草稿时显示发送与排队提示。共享审批卡默认展开，
  拒绝与允许同一行，其余可用动作各占一行；用户问题保留选项、自由文本和编辑器预填。
- **设置**：外观、语言、本机名称、版本与协议版本，以及断开连接；不复制执行端的
  提供方配置或项目管理。

## 连接状态

| 状态 | 呈现与行为 |
| --- | --- |
| 正在连接 | 尚未收到初始索引，显示旋转图标与连接说明 |
| 已连接 | 索引已就绪且链路正常；对话页不显示连接状态胶囊 |
| 重连中 | 保留内容，显示重试次数 |
| 离线 | 断线达到 30 秒后显示；临时网络故障仍继续重试 |
| 证书变化 | 优先显示明确错误及重新配对入口；原生连接停止重试该身份 |

状态放在列表页顶栏副标题或对话页状态胶囊。离线时保留最后收到的副本供阅读，
已访问对话保留事件；未访问对话可能只有列表摘要。写入动作被禁用，重连后重新订阅
当前对话。原生应用回到前台、浏览器页面重新可见时可打断退避，立即尝试连接。

## 视觉与输入

共享颜色、字体与材质来自 [主题](../themes/tcode.json) 和
[material.rs](../crates/ui/src/material.rs)，手机窗口的画布压平为不透明颜色。
DM Sans 与桌面使用同一字体资源；Android 另注册 Lilex 等宽字体及随包的 Noto
Color Emoji。两个平台入口安装同一个 `tcode_ui::assets::Assets`；原生调试构建也
将字体和 SVG 嵌入安装包，不读取开发机器的资源路径。

- 页面左右留 16pt；顶栏 52pt，加上顶部安全区。图标按钮触控区为 44×44pt，
  使用统一描边图标和前景色。
- 紧凑 composer 圆角为 16pt；外壳 sheet 顶部圆角为 14pt，使用实底、遮罩、
  软阴影和 36×5pt 抓手。其他共享组件使用自己的材质半径。
- 空态为图标、标题、短说明及必要的主动作，居中且限制宽度；不显示桌面快捷键。
- 输入控件和按钮不能依赖 hover。长文本、模型列表与可变数量选项需有可滚动区域，
  控件换行或滚动，避免截断可选值。
- 安全区和键盘使用 `WindowInsets`，页面底部取 `max(safe_area.bottom, ime.bottom)`。
  Android 恢复前台后重新上报 insets，输入区应留在软件键盘上方。
- 原生扫码由 iOS 的 AVFoundation 和 Android 的 CameraX/ML Kit 提供；成功、取消和
  错误都经宿主一次性返回配对界面。模拟器的权限/取消流程不能证明真实相机识别有效。

中文使用执行端、对话、轮次、排队、引导、停止等一致术语；文案从
`locales/zh-CN.yml` 与 `locales/en.yml` 取值。错误说明用户可以采取的下一步，
不把内部协议字段或实现细节放进产品流程。

## 开发与验证

iOS 和 Android 的接入与构建说明分别见
[gpui-ios](../crates/platform/gpui-ios/README.md) 和
[gpui-android](../crates/platform/gpui-android/README.md)。浏览器构建见
[远程指南](remote.md#build-with-the-browser-client)，编译门禁以
[CONTRIBUTING.md](../CONTRIBUTING.md) 和 CI 为准。

改动共享界面时检查两套主题、窄屏、长文案、键盘遮挡和离线只读状态。涉及原生桥接时
在对应平台验证：配对、发起真实轮次、审批、返回导航、断开及恢复连接；扫码识别需要
带相机的设备。将本次验证证据放入 PR，不把一次验收的截图和机器运行日志长期作为规范。
