# tcode 手机端设计规范

状态：权威规范（2026-09-05）。手机端（iOS / Android，以及后续的浏览器端）
一切界面、文案、交互以此为准；与代码冲突时改代码。配套计划见
`docs/plans/remote-and-mobile.md`。

## 0. 产品定位：一台随身的「监督器」

手机端不是缩小的桌面版，更不是 IDE。它做且只做四件事，按频率排序：

1. **看**：哪些对话在跑、跑到哪、有没有卡住或出错。
2. **批**：执行端弹出的权限请求，在手机上一键放行或拒绝。
3. **说**：追加一句话、引导正在进行的轮次、打断。
4. **开**：在某个项目里新开一个对话，把任务派出去。

所有真正的工作都在**执行端**（电脑或服务器上运行的 tcode）完成；手机端只是它
的一块屏幕。这个前提决定了整个界面：没有终端、没有 diff 编辑、没有文件
选择器、没有本地设置项。

### 0.1 与桌面端同源（最高优先级原则）

手机端**不是重新画一套界面**，而是桌面端同一批组件在窄屏上的排版：

- 对话列表页 = 桌面端侧栏（`tcode_ui::sidebar::SessionsSidebar`）铺满整屏：
  同样的项目文件夹树、同样的对话行（标题 + 相对时间）、同样的字体与间距。
- 对话页 = 桌面端 `tcode_ui::chat::ChatView` 铺满整屏：同样的时间线组件
  （用户气泡与 Copy/Edit、助手 Markdown、「执行了 1 条命令 · 编辑了 1 个文件 ·
  2 次工具调用」工作日志行、变更文件卡、思考块、计划卡、审批卡）。
- 输入区 = 桌面端 `tcode_ui::composer::Composer`：同一张圆角卡片，文本域在
  上，底行是模型选择、审批模式、模式切换，右下角圆形发送/停止按钮。
- 字体 = 桌面端同款：UI 用 DM Sans（`tcode_ui::assets::DM_SANS` 必须在手机端
  注册），等宽用系统等宽。色板 = `themes/tcode.json`。

手机端自己只负责三样东西：**导航外壳**（顶栏、返回、栈）、**手机专有页**
（执行端列表、配对、设置 sheet）、以及**窄屏适配**（在 `tcode-ui` 里加
「紧凑模式」而不是在手机端复制组件）。凡是桌面端已有的组件，手机端一律
复用；桌面组件在窄屏下放不下的，去 `tcode-ui` 里改成可响应，不在手机端重画。
桌面端不需要的东西（终端、预览、diff 面板、右侧面板、拖拽分栏）在紧凑模式
下隐藏，而不是删除。

## 1. 术语表（最终裁定）

界面文案、代码标识、文档一律使用下表。桌面端「设置 → 远程」里凡是指
「运行 tcode 主机进程的那台机器」的「主机」，一并改为「执行端」。

| 概念 | 简体中文 | English | 说明 |
|---|---|---|---|
| 运行任务的那台 tcode | 执行端 | Host | 用户原话。不用「主机 / 服务器 / 远程端」 |
| 手机上的 tcode | 手机端 | tcode for iPhone / Android | 只在「关于」里出现产品名 |
| 手机在执行端眼中 | 设备 | Device | 执行端的「已配对设备」列表 |
| 建立信任的过程 | 配对 | Pair / Pairing | 动词「配对」，名词「配对」 |
| 六位数字 | 配对码 | Pairing code | 不叫「口令 / 验证码 / PIN」 |
| `tcode://pair?...` | 配对链接 | Pairing link | 二维码的内容 |
| 扫二维码 | 扫码配对 | Scan QR code | |
| 项目（工作目录） | 项目 | Project | 与桌面端一致 |
| 一段会话 | 对话 | Thread | 与桌面端一致，不用「线程 / 会话 / 任务」 |
| 新建 | 新建对话 | New thread | |
| 一次请求-响应 | 轮次 | Turn | 「停止当前轮次」 |
| 正在生成 | 工作中 | Working | 与桌面端一致 |
| 等权限 | 待审批 | Needs approval | 与桌面端一致 |
| 等用户答题 | 待回答 | Needs your answer | 与桌面端一致 |
| 新内容未看 | 未读 | Unread | |
| 结束的对话 | 已完成 | Done | 列表副标题用；无轮次在跑 |
| 出错 | 出错 | Failed | 列表副标题用 |
| 追加发送（等本轮结束） | 排队 | Queue | 与桌面端一致 |
| 插入本轮 | 引导 | Steer | 与桌面端一致，不用「插话 / 打断」 |
| 中止 | 停止 | Stop | |
| 工具活动折叠组 | 工作日志 | Work log | 与桌面端一致 |
| 思考 | 思考中 / 已思考 | Thinking / Thought | 与桌面端一致 |
| 允许一次 | 允许 | Allow | 审批按钮 |
| 本对话内不再问 | 本对话始终允许 | Always allow in this thread | 审批的第三个动作 |
| 拒绝 | 拒绝 | Deny | |
| 审批模式 | 审批模式 | Approval mode | 三档：监督模式 / 自动接受编辑 / 完全访问 |
| 模型 | 模型 | Model | |
| 推理强度 | 推理强度 | Effort | 与桌面端一致 |
| 连接状态 | 已连接 / 正在连接 / 重连中 / 离线 | Connected / Connecting / Reconnecting / Offline | 见 §4 |
| 手机自己的名字 | 本机名称 | This device's name | 配对时上报给执行端 |

英文文案风格：句首大写、无句号的短标签；正文句子完整。中文文案：不用
「您」，不用感叹号，标点用全角，数字与中英文之间留空格。

文案规则（每条新字符串都对照）：

1. 不写教程。界面只说这一步要做什么，不解释产品如何工作；帮助文字 ≤ 1 句。
2. 不出现命令行、快捷键、平台名（Mac、Windows）。执行端是「电脑或服务器」。
3. 不重复上下文已经给出的信息：标签是「地址」，占位就不再说「执行端的」；
   卡片已有「待审批」标记，标题就不再说「请求」。
4. 按钮 = 动词 + 对象（「配对执行端」「断开连接」），或单个动词（「允许」）。
5. 错误 = 发生了什么 + 用户能做的一步（「配对码错误或已过期，请在执行端重新
   生成」），不写「失败」「错误」以外的技术词。
6. 状态词只在有信息量时出现：工作中 / 待审批 / 待回答 / 出错；空闲不标注。
7. 同一概念全程一个词（§1 术语表）；中英文一一对应，不各自发挥。

## 2. 信息架构

```
启动
 ├─ 有「上次使用的执行端」 → 直接进入 [对话列表]（顶部显示「正在连接…」）
 └─ 否则 → [执行端]

[执行端]  ──点执行端──▶  [对话列表]  ──点对话──▶  [对话]
   │                        │  ├─ ＋ ──▶ (选择项目) ──▶ [对话]（新草稿）
   ├─ 配对 ──▶ (配对)        │  └─ ⚙ ──▶ (设置)
   └─ 长按 ──▶ (移除执行端)   └─ ‹ 执行端（返回，断开连接）
```

- 三级栈：执行端 → 对话列表 → 对话。方括号是全屏页，圆括号是从底部升起
  的 sheet。
- 返回：iOS 用左上角「‹ 上一级」文字按钮；Android 同时响应系统返回键。栈底
  再按返回 = 退出应用。
- 切换执行端就是回到 [执行端] 再点另一个。一次只连一个执行端。
- 没有 tab bar。三个层级是线性的，tab 会把「执行端」和「对话」并列，误导用户。

## 3. 外壳与视觉身份（第二版，2026-09-05 评审后重写）

第一版实现的问题（逐页评审结论，作为本节每条规则的出处）：

- 整体：平铺的浅灰底 + 灰色卡片 + 饱和蓝按钮，没有桌面端「霜面仪表」的任何
  特征——没有纸面/机壳分层、没有发丝线、没有品牌字标、没有蓝色墨线体系。
  看起来像表单原型，不像 tcode。
- 桌面 chrome 泄漏：列表页顶栏下面又出现一排「对话 · 文件夹 · 网格 · ＋」
  （侧栏的排序/布局控件），同屏两个「＋」；空态文案「添加项目 · 或按 Ctrl+K
  搜索」出现在手机上；列表行保留桌面的常驻选中高亮（手机导航离开后毫无意义）。
- 顶栏：返回键是饱和蓝的「‹ 执行端」文字，右侧「＋」细线蓝、齿轮实心蓝，
  粗细与颜色不一致；对话页标题两行挤在返回键旁边。
- 输入区与时间线之间没有分隔；轮次进行中输入区出现「转圈 + 发送 + 停止」
  三件并排的怪异一行。
- 设置里「关于」把「手机端」当产品名；配对/设置 sheet 没有抓手、没有统一的
  标题栏样式。
- 页面切换和 sheet 弹出没有任何动效，整机感觉「跳」。

### 3.0 通用规则

- **材质**：页面底色用桌面的 T1 纸面（`material::content_surface`），不是 T0
  机壳灰。卡片 = T2 叠色 + 发丝边（`material::group` / `grouped`）。sheet =
  T3 实底 + 发丝边 + 大软阴影 + 顶部抓手（36×5，`muted` 30%）。分隔一律用
  `material::faded_hairline`，禁止通栏 1 px 线。
- **蓝色墨线**：只用于主按钮、当前选中/聚焦、进行中状态；返回键、图标按钮、
  次要文字用 `foreground` / `muted_foreground`，不用蓝。
- **顶栏**（`NavBar`，高 52 + 安全区，纸面底，下方一条渐隐发丝线）：左侧返回
  = 20 pt chevron 图标 + 上一级标题（15 pt，`foreground`），触控区 44；中间
  标题 17 semibold 单行省略，副标题 13 muted；右侧最多两枚 44×44 图标按钮，
  统一用 `tcode_ui::icon::Icon` 描边图标、`foreground` 色、20 pt。
- **导航**：用 `gpui_base::NavStack` 承载三级页面，push/pop 带 200 ms 横向
  位移 + 淡入（`NavMotion`），sheet 用 `Presence` 做 180 ms 自底部滑入、遮罩
  淡入。Android 返回键 = `NavStack::pop`。
- **列表行**：手机不显示常驻选中态，只有按下态（8% 叠色）；行高 ≥ 56；行间
  不画线，靠 12 pt 垂直留白分隔。
- **空态**：一律「图标（24，muted）+ 标题（17 semibold）+ 正文（15 muted，
  ≤ 2 行）+ 可选主按钮」，垂直居中，最大宽 280。禁止任何桌面快捷键文案。
- **品牌**：执行端页顶部用 `material::brand_wordmark`（tcode 字标）压在大标题
  上方，13 pt，这是全应用唯一出现品牌的地方（加上「关于」）。

### 3.1 执行端（启动页）

- 顶部：字标 → 大标题「执行端」（28 semibold）→ 一行说明（15 muted）
  「运行在电脑或服务器上的 tcode。手机只负责查看和操作。」
- 列表：每台执行端一张 T2 卡片（圆角 12，内边距 14，高 ≥ 72）：
  - 行 1：名称（17 semibold）；右侧：若为上次使用 → 胶囊「上次使用」
    （`semantic_chip`，muted）。
  - 行 2（14 muted）：`192.168.1.6:47420 · 10 分钟前连接过`。
  - 行 3（12 muted，等宽）：证书指纹前 4 组 `A1B2 C3D4 E5F6 7788`（P4c 之后）。
  - 整卡可点；长按 → sheet「移除执行端」。无 chevron（整卡已是明显可点）。
- 底部主按钮「配对执行端」（高 50，圆角 12，主色，压在底部安全区之上，与列表
  之间留 16）。
- 空态：图标 = 双屏图标；标题「还没有配对的执行端」；正文「打开执行端的
  “设置 → 远程”开启托管，然后在这里配对。」；主按钮同上。

### 3.2 配对（sheet）

- 标题栏：抓手 + 「配对执行端」（17 semibold，左）+ 「取消」（15，
  `foreground`，右）。
- 若支持相机：主色描边按钮「扫码配对」（高 50）；下方一行居中 13 muted
  「或手动输入」。
- 「附近的执行端」（P4c 之后）：发现到的执行端以小卡片横向排列或最多 3 行
  列表，点选 → 填入地址/端口/指纹并聚焦配对码。
- 表单：标签 13 muted 在上；输入框高 48、圆角 12、T2 底；地址 / 端口 / 配对码
  （24 pt 等宽，字距 0.2 em）。三项之间 16。
- 指纹（P4c 之后）：配对成功前显示「连接后将显示并固定执行端证书」；成功后
  在执行端卡片上显示。
- 说明与错误：说明 13 muted；错误一行 13 `danger`，出现在表单上方，不用弹窗。
- 主按钮「配对」（高 50），进行中「正在配对…」并禁用表单。
- 不显示配对码有效期之外的任何操作指引；帮助链接不做。

### 3.3 对话列表

- 顶栏：左「‹ 执行端」；中：执行端名称 + 连接状态副标题（§4）；右：「＋」
  （新建对话）与「设置」两枚图标按钮。**这是本页唯一的「＋」**。
- 搜索：顶栏下方一枚胶囊搜索框（高 40，T2 底，放大镜图标 + 占位「搜索对话」），
  点击进入即得搜索（沿用侧栏的搜索逻辑）。
- 内容 = `SessionsSidebar` 紧凑模式，**移除**桌面的「对话/项目」标题行与
  排序/布局/添加控件（紧凑模式下不渲染，而非隐藏后留空）。
- 项目分组头：文件夹图标 16 + 项目名（14 semibold，`foreground`）+ 右侧对话数
  （13 muted）+ 折叠 chevron；上边距 20，下边距 6；点击折叠。
- 对话行（高 ≥ 56，左右 16）：
  - 左：20×20 状态位（工作中 = 主色旋转圈；待审批 = `warning` 圆点带「!」；
    待回答 = 主色圆点带「?」；未读 = 主色实心小圆点；无 = 留空但占位）。
  - 中：标题 16（未读 semibold），下一行 13：状态词 · 相对时间（状态词按 §4/§1
    配色）。空闲的对话不写状态词，只显示相对时间——「已完成」不是信息。
  - 右：无 chevron。长按 → 上下文菜单（归档、标记未读、重命名——复用侧栏菜单）。
- 待审批/待回答的行整行加 6% `warning`/主色底。
- 「＋」→ sheet「选择项目」；只有一个项目时直接新建。
- 空态：图标 = 文件夹；「这台执行端上还没有项目」+「在执行端上添加项目后会
  自动出现在这里。」无按钮。
- 连接中：3 行骨架行（T2 底 30%）；离线：列表保留，只改状态副标题。

### 3.4 对话

- 顶栏：左「‹ 对话」；中：对话标题（17 semibold 单行省略）+ 项目名副标题；
  右：仅在非「已连接」时显示连接状态胶囊（§4）。
- 时间线 = `ChatView` 紧凑模式：左右 16，段间距 12；`ChatView` 自带的标题栏、
  Git/Open 动作、终端/预览/diff 开关一律不渲染。
- 时间线底部与输入区之间：渐隐发丝线 + 8 pt 留白；输入区区域用纸面底，随
  键盘上移（IME inset）。
- 输入区 = `Composer` 紧凑模式：
  - 卡片圆角 16，文本域最小高 44，最多 5 行。
  - 底行左：模型 chip（图标 + 名称，13）与审批模式 chip；放不下时审批模式换到
    第二行，永远不超过两行。
  - 底行右：一枚 40×40 圆形主按钮。空闲 = 发送箭头；进行中 = 红色停止方块；
    进行中且文本域非空 = 发送箭头 + 按钮下方 10 pt 小字「排队」。**不再同时
    显示三个控件**。
  - 语音、@ 补全、斜杠命令、附件粘贴入口不渲染。
- 新建对话（草稿）的空态：图标 = 对话气泡；标题「在 {项目} 中开始新对话」；
  正文「消息会发到执行端上的 {提供方 · 模型}。」无按钮，输入框自动聚焦。
- 审批卡 / 待回答卡 / 队列条：沿用桌面组件的紧凑排版（审批四个动作：
  [拒绝][允许] 一行，「本对话始终允许」「取消本轮」各占一行，见已修的实现）。
- 「↓ 回到最新」胶囊：右下角，T3 底，发丝边。

### 3.5 模型与模式（sheet）

- 标题栏同 §3.2。内容 = 桌面模型选择器（提供方竖栏 + 搜索 + 列表）紧凑排版，
  行高 52，当前项打勾，收藏星保留。
- 底部固定两组分段控件：「推理强度」（仅当提供方支持）与「审批模式」，
  分段控件高 40、圆角 10、T2 底、选中段 T3 实底 + 发丝边。选择即生效。

### 3.6 设置（sheet）

- 分组卡（`material::grouped`）：外观（分段控件）、语言（分段控件）、本机名称
  （输入框）。
- 「关于」：一行 `tcode` 字标 + 版本号 + 协议版本，13 muted。不再出现
  「手机端」作为名称。
- 底部文字按钮「断开连接」（`danger`，高 44）。

## 4. 连接状态（贯穿全局）

| 状态 | 文案 | 样式 | 触发 |
|---|---|---|---|
| 正在连接 | 正在连接… | 旋转圈 + muted 文字 | 首次连接尚未收到快照 |
| 已连接 | 已连接 | `success` 小圆点 + muted 文字；对话页不显示 | 链路正常 |
| 重连中 | 重连中 · 第 3 次 | `warning` 旋转圈 + `warning` 文字 | 掉线后自动重试 |
| 离线 | 离线 | `danger` 圆点 + `danger` 文字 | 连续失败超过 30 秒后 |
| 证书变化 | 执行端证书已变化 | `danger` 文字，点开说明并提供「重新配对」 | 指纹不匹配（P4c） |

- 状态只在顶栏副标题（列表页）和顶栏右侧胶囊（对话页，非已连接时）显示，
  不用横幅、不用弹窗、不用 toast。
- 应用回到前台立刻重试一次，不等退避计时。
- 「离线」不清空任何内容：列表和时间线保留最后的副本，只禁用会写入执行端
  的动作。

## 5. 视觉系统（手机专用值）

沿用 `docs/DESIGN.md` / `docs/visual-redesign.md` 的字体、色板与材质常量
（`crates/ui/src/material.rs`），手机窗口不透明，画布色压平。

| 项 | 值 |
|---|---|
| 字体 | UI：DM Sans（`tcode_ui::assets::DM_SANS`，CJK 由系统级联）；等宽：系统等宽 |
| 字号 | 大标题 28/34 semibold · 标题 17/22 semibold · 正文 16/22 · 次要 14/20 · 说明 13/18 · 等宽 14/20 |

## 6. 不做的事（v1 明确排除）

终端、预览浏览器、diff 面板、文件 @ 补全、附件上传、语音输入、归档管理、
重命名、搜索、多执行端同时连接、后台推送通知。以上都有存在理由，但都不在
「监督器」的前四件事里。

## 7. 验收

- 每个屏幕的每种状态（含空态、连接中、离线、错误）都有截图，逐张对照本
  规范；文案逐字对照 §1 与各屏幕小节；`locales/zh-CN.yml` 与 `en.yml` 的
  `mobile.*` 键同步。
- 真机流程：iPhone 模拟器与 Android 模拟器分别对本机上的 `tcode-headless`
  完成：配对 → 看到项目与对话 → 新建对话并发送一轮 → 在手机上审批 →
  杀掉执行端看到「重连中」→ 重启执行端自动恢复。

## 实现备注

- 手机偏好保存在 `mobile.json`；返回执行端列表保留上次使用记录，移除该执行端时清除。离线展示在连续断线 30 秒后切换，传输仍继续重试。
- §0.1 优先：对话列表、时间线、审批、待回答、队列和输入区均宿主桌面实体；搜索复用 `CommandPalette`，弹窗和通知复用 `OverlayHost`。保留桌面审批动作和工作日志结构，不另画手机版本。
- 紧凑输入区允许底行换行：模型、模型参数、发送/停止在前，审批模式与构建/计划在下一行；运行中继续换行以保持 44 pt 触控区。模型参数沿用桌面独立选择器。
- 模型、参数、审批选择器及回退菜单复用原内容与 `PopoverState`，仅容器改为底部 sheet；最多为视口高度减 64 pt，模型列表高 360 pt，底部内边距 32 pt。紧凑选择器取消淡入动画；其无障碍容器使用命名分组，避免 GPUI 将嵌套对话框误识别为另一个窗口。
- 紧凑审批卡默认展开，四个桌面动作排列为两行两列；所有按钮保持桌面行为，手机标签按 §1 替换。复制按钮在触屏上常显，紧凑平铺列表取消位置过渡。未访问对话离线时只有缓存状态；已访问对话保留事件副本用于只读浏览，断线期间的写命令被拒绝，重连后重新选择当前对话。
- DM Sans 使用桌面同一字体资源，半透明画布按桌面不透明窗口规则压平。执行端与配对屏保留原布局。
- iOS 与 Android 入口安装桌面同一 `Assets`，移动端统一注册 DM Sans；Android 另注册 Lilex 作为等宽字体。原生调试构建把现有字体与 SVG 嵌入包内，列表顶栏的新建和设置按钮使用 `IconName::Plus` / `IconName::Settings`，不再依赖字体里的 Unicode 符号。
- `MobileHost::insets` 默认兼容旧 `safe_area` 实现；原生宿主返回完整 `WindowInsets`。页面底部使用 `max(safe_area.bottom, ime.bottom)`，Android 回到前台时重新上报 root insets，Composer 在两端软件键盘上方保持可见。
- iOS 用 `UIDevice.current.name`、Android 用 `Build.MODEL` 初始化本机名称；扫码分别桥接 AVFoundation QR metadata output 与 CameraX + ML Kit，并把成功、取消或错误一次性送回配对 sheet。模拟器验收覆盖了权限提示、Android 原生扫描页以及取消后的无崩溃返回；iOS 模拟器没有相机，未执行实际二维码识别。
